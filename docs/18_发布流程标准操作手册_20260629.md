# ZL.Iot.Sdk 发布流程标准操作手册

> **核心原则：所有 NuGet 发布由 GitHub Actions 自动完成，禁止手动 dotnet nuget push。**

---

## 发布链路总览

```
代码变更 → git tag vX.Y.Z → push → GitHub Actions → build/pack/obfuscate → push to nuget.org
```

当前版本固定为 `2.2.1`，不允许随意提升版本。

---

## 标准发布流程（3 步）

### 第 1 步：触发 GitHub Actions 发布

```bash
cd /Users/dingyuwang/0-X/iot-sdk

# 1. 确保代码已提交并推送到 main
git add .
git commit -m "chore: 准备发布 2.2.1"
git push origin main

# 2. 打版本 tag 并推送（触发 GitHub Actions）
git tag v2.2.1
git push origin v2.2.1
```

**GitHub Actions 自动完成**：
- restore → build → pack → obfuscate（Obfuscar）
- 上传 nupkg 为 artifact
- 推送到 **nuget.org**（通过 OIDC 临时 API Key，不长期留存）

**手动触发（workflow_dispatch）**：
- 在 GitHub 仓库的 Actions → "Publish iot-sdk to NuGet" 中手动运行
- 可指定版本号、跳过混淆、dry-run 等参数

### 第 2 步：同步下游消费项目

```bash
cd /Users/dingyuwang/0-X/iot-sdk

# dry-run 预览变更（必须！）
zl-pipeline sync-consumers 2.2.1 --dry-run

# 确认无误后执行同步
zl-pipeline sync-consumers 2.2.1
```

**sync-consumers 自动完成**：
1. 扫描 artifacts/ 中对应版本的 nupkg
2. 更新 tmom `Directory.Packages.props` 中的版本号
3. 编译验证 tmom 可正常构建
4. （可选）自动 git commit + push（需设置 `"autoCommit": true`）

### 第 3 步：验证

```bash
# 验证 NuGet 上发布的包
zl-pipeline check ZL.Dao.IotDevice 2.2.1

# 验证 iot-sdk 自身编译
zl-pipeline verify 2.2.1
```

## pipeline.json 配置说明

```jsonc
{
  "$schema": "https://raw.githubusercontent.com/usethink/ZL.Pipeline/main/schemas/pipeline-schema.json",
  "version": "1.0",
  "projects": [
    {
      "name": "ZL.Dao.IotDevice",          // 项目名
      "csproj": "src/domain/ZL.Dao.IotDevice/ZL.Dao.IotDevice.csproj",  // csproj 相对路径
      "obfuscate": true                     // 是否混淆
    }
    // ... 22 个项目
  ],
  "nugetSource": "https://api.nuget.org/v3/index.json",
  "publishTimeout": 120,
  "dryRun": false,
  "consumers": [                            // ← 下游消费项目
    {
      "name": "tmom",                      // 消费项目名称
      "path": "/Users/dingyuwang/0-X/tmom", // 项目根目录（绝对路径）
      "cpmFile": "Directory.Packages.props", // CPM 文件路径
      "buildTarget": "api/TMom.Device.Runtime.Host/TMom.Device.Runtime.Host.csproj", // 编译验证目标
      "autoCommit": false                  // true=自动 git commit+push
    }
  ]
}
```

> **注意**：`pipeline.json` 主要用于 `zl-pipeline sync-consumers` 和本地打包元数据，实际 NuGet 推送由 `.github/workflows/publish.yml` 处理。

## 常见问题

### Q: 如何触发一次发布？
A: 推送带 `v` 前缀的 tag，例如 `git push origin v2.2.1`。GitHub Actions 会自动触发。

### Q: 可以在本地直接 push 到 nuget.org 吗？
A: 禁止。所有 nuget.org 推送必须通过 GitHub Actions，确保可追溯、不泄露长期 API Key。

### Q: sync-consumers 报告 "未找到 nupkg"
A: 先运行 GitHub Actions 生成 artifacts/ 目录下的 nupkg，或确认 tag 已推送且 Actions 运行成功。

### Q: sync-consumers 编译验证失败
A: 说明版本升级引入了破坏性变更。先修复代码，再重新发布。

### Q: autoCommit 能否设为 true？
A: 前提是下游项目 git remote 可正常 push（无权限问题）。tmom 在 Gitee 上需确保有推送权限。

### Q: 新消费项目如何接入？
A: 在 `pipeline.json` 的 `consumers` 数组中添加配置项即可。

## 历史教训（不再犯的错）

| 错误 | 对策 |
|---|---|
| 手动 `dotnet build/pack/push` | GitHub Actions 自动处理，禁止手动推送 |
| 手动 `cp` nupkg 到 local-feed | 已废弃，所有包统一从 nuget.org 拉取 |
| 手动编辑 csproj 切换引用方式 | csproj 的切换是一次性变更，完成后不再改动 |
| 手动编辑 Directory.Packages.props | 必须用 `zl-pipeline sync-consumers` |
| 忘记 git push | 后续通过 CI 或 autoCommit 自动化解决 |
| 忘记先 dry-run | 所有操作必须先 `--dry-run` 再执行 |
| 本地长期保存 NUGET_API_KEY | GitHub Actions 使用 OIDC 临时密钥，不落地 |

## 附录：GitHub Actions 发布配置

**文件位置**：`.github/workflows/publish.yml`

**触发条件**：
- `push` tag: `v*`（例如 `v2.2.1`）
- `workflow_dispatch`：手动触发，可输入版本号、跳过混淆、dry-run

**核心步骤**：
1. `actions/checkout@v4` 拉取代码
2. `actions/setup-dotnet@v4` 配置 .NET 8
3. `python3 scripts/publish_all.py` 执行构建、打包、混淆
4. `actions/upload-artifact@v4` 上传 nupkg
5. `NuGet/login@v1` 通过 OIDC 获取临时 NuGet API Key
6. `dotnet nuget push` 推送到 nuget.org

**安全特性**：
- 使用 GitHub OIDC 进行 NuGet 认证，不长期存储 API Key
- 仅在 tag push 或手动触发时发布，避免日常 push 误触发
