`ZL.ConnectionGuard` / `ZL.Script` / `ZL.Shared` / `ZL.DataProcessing` 是早期副本

## 2. ZL.Script 回填的三处缺陷修复

来源：ZL.Simulator 侧 2026-10-03 的定位与修复（当时两处静默使**表达式能力大面积不可用**，
协议模板的 `=表达式` 长期失效）：

1. **实参个数不匹配**：`BuildArgs` 只按 `UsedParameters` 传参，而 DynamicExpresso 要求
   实参数与**声明的形参**一致 → 任何未用满上下文的表达式都抛
   `Arguments count mismatch`。改为按 `DeclaredParameters` 声明顺序全量传参。
2. **助手库注册方式错**：静态类被 `SetVariable(name, type)` 绑成 `Type` 对象，
   `Format.Hex(255)` 抛 `No applicable method 'Hex' exists in type 'Type'`——
   Hex/Binary/Bit/BinaryLogic/Checksum/Crc/Format/Sim 全部不可用。改为 `Reference(type, alias)`。
3. **缓存键缺参数签名**：缓存只按表达式文本，先以 A 上下文解析、再以 B 上下文调用会
   互相污染。缓存键改为「表达式 + 形参名与值类型签名」。

回归锁：`tests/ZL.Script.Tests/ScriptEngineTests.cs`（6 用例，自 ZL.Simulator 移植，
双 TFM 通过）。本工程此前无测试覆盖。

## 3. ZL.ConnectionGuard 回填的异步整理

来源：ZL.Simulator 侧 2026-10 早期的 P1 异步优化（commit c79ffd1 / 8a13ae7 方向），
内容为机械性收敛，无行为语义变化：

- 全部 `await` 补 `ConfigureAwait(false)`（库代码规范）；
- `ReadAsync(buffer, 0, len)` → `ReadAsync(buffer.AsMemory(0, len))`；
- `UdpClientAdapter`：`receiveTask.Result` → `await receiveTask`（避免同步阻塞包装）。

涉及 8 个文件：`ConnectionGuard.cs` + 7 个适配器（Can/Lin/Hsl 三个本就一致，未动）。
`tests/ZL.ConnectionGuard.Tests`（关闭风暴修复的回归锁）通过，行为无回归。
